# WO 작업 규칙 (이 폴더 전용)

이 폴더(`docs/work-orders/`)의 파일을 생성/수정/조회할 때는 **반드시** 아래 규칙을 따릅니다.
이 문서는 `PROGRESS.md` 갱신의 단일 진실 소스(SSOT)입니다.

## 절대 원칙 (가장 중요)

1. **각 슬래시 커맨드는 자기 칸만 갱신한다.** 다른 칸은 절대 건드리지 않는다.
2. **각 슬래시 커맨드는 자기 작업이 끝나면 즉시 종료한다.** 다음 단계의 커맨드를 자동으로 호출하거나 시뮬레이션하지 않는다. 사용자가 명시적으로 다음 커맨드를 입력할 때까지 대기한다.
3. **다른 WO의 행은 절대 건드리지 않는다.**
4. **표가 손상되었거나 의미가 모호하면 즉시 사용자에게 보고하고 작업을 중단한다.** 임의로 "복구"하거나 "정리"하지 않는다.

## PROGRESS.md 갱신 규칙

`PROGRESS.md`는 WO 파이프라인의 현재 진행 상태를 한눈에 보기 위한 문서입니다.

### 1. 표 구조 (절대 변경 금지)

| WO | check | fix-check | start | review | fix-review |
|----|:---:|:---:|:---:|:---:|:---:|
| WO-XXX | O | - | O | O | - |

- **컬럼은 정확히 6개** (WO + 5단계). 늘리거나 줄이지 않습니다.
- 단계 컬럼 순서는 `check → fix-check → start → review → fix-review` 고정.
- 정렬: 가장 최근에 갱신된 WO가 **맨 위**에 오도록 정렬합니다.

### 2. 셀에 들어갈 수 있는 값 (이 3개 외 절대 금지)

| 기호 | 의미 |
|------|------|
| `O` | 통과 / 완료 |
| `X` | 실패 (그 단계 자체의 결과) |
| `-` | 미진행 또는 불필요 |

- **반드시 대문자** `O`/`X`만 허용. 미진행은 하이픈 `-` 하나.
- 사용 금지 예시: `o`, `x`, `✓`, `✅`, `❌`, `OK`, `완료`, `done`, 빈 칸 등.

### 3. 핵심 해석 규칙 (반드시 이해)

**각 칸은 그 단계의 결과만 기록한다. 다른 칸을 건드리지 않는다.**

- `check` 칸은 `/check`의 결과만 기록.
- `fix-check` 칸은 `/fix-check`의 결과만 기록.
- `start` 칸은 `/start`의 결과만 기록.
- `review` 칸은 `/review`의 결과만 기록.
- `fix-review` 칸은 `/fix-review`의 결과만 기록.

**"단계 통과" 판정**:
- check 단계 통과 = `check`가 `O` **또는** `fix-check`가 `O`
- review 단계 통과 = `review`가 `O` **또는** `fix-review`가 `O`

즉, `check=X` `fix-check=O`이면 **이미 해결된 상태**입니다. 다시 `/check`를 돌릴 필요 없습니다. `X`는 그 칸의 마지막 결과일 뿐이지 "현재 미해결"을 의미하지 않습니다.

### 4. 단계별 갱신 규칙

#### `/check WO-XXX`
- 해당 WO 행이 없으면 새 행을 만들고 5칸 모두 `-`로 초기화.
- 검수 결과 PASS → `check` 칸을 `O`로.
- 검수 결과 FAIL → `check` 칸을 `X`로.
- **다른 칸은 손대지 않음.**

#### `/fix-check WO-XXX`
- 모든 문제 해결 → `fix-check` 칸을 `O`로.
- 미해결 / 사용자 결정 대기 → `fix-check` 칸을 `X`로.
- **`check` 칸은 절대 건드리지 않음.** (X로 남아있어도 정상)

#### `/start WO-XXX`
- 선행 단계 통과 검증: `check`가 `O` 또는 `fix-check`가 `O`여야 함.
  - 둘 다 아니면 작업 시작하지 않고 사용자에게 보고.
- 작업 완료 → `start` 칸을 `O`로.
- **다른 칸은 손대지 않음.**

#### `/review WO-XXX`
- 검토 결과 PASS → `review` 칸을 `O`로.
- 검토 결과 FAIL → `review` 칸을 `X`로.
- **다른 칸은 손대지 않음.**

#### `/fix-review WO-XXX`
- 모든 문제 해결 → `fix-review` 칸을 `O`로.
- 미해결 / 사용자 결정 대기 → `fix-review` 칸을 `X`로.
- **`review` 칸은 절대 건드리지 않음.** (X로 남아있어도 정상)

### 5. "현재 작업" 라인

`PROGRESS.md` 상단의 `**현재 작업**:` 라인은 **지금 진행 중인 단일 WO와 단계**를 가리킵니다.

- 슬래시 커맨드 시작 시: `**현재 작업**: WO-XXX (단계: <스킬 이름>)`로 갱신.
  - 스킬 이름은 `check` / `fix-check` / `start` / `review` / `fix-review` 다섯 중 하나.
  - 더 세밀한 sub-state(`CHECK_RUNNING`/`CHECK_QUEUED` 등)는 **wo-dashboard UI가 DB에서 직접 조회**해 표시합니다. 슬래시 커맨드는 sub-state를 쓸 필요 없습니다.
- 커맨드 정상 종료 시: `**현재 작업**: (없음)`으로 비웁니다.
- **다음 단계를 자동으로 시작하지 마십시오.** 사용자가 다음 슬래시 커맨드를 명시적으로 입력할 때까지 대기합니다.

> **참고**: 파이프라인 상태 표기는 3계층(DB sub-state / ROADMAP 한국어 상태 / PROGRESS.md 셀)으로 나뉩니다. 전체 매핑은 wo-dashboard의 `docs/STATE_MAPPING.md` 참조.

### 6. "현재 단계 메모" 섹션

표 아래의 자유 형식 메모. 진행 중 발견한 이슈/막힌 지점/다음 액션을 짧게 기록합니다.

- 형식: `- WO-XXX / <단계>: <내용>`
- 해당 WO의 모든 단계가 끝나면 메모를 정리합니다.

### 7. 안전장치 (갱신 전 반드시 확인)

1. 갱신하려는 WO 번호가 현재 커맨드 인자와 정확히 일치하는가?
2. 표의 컬럼이 정확히 6개인가?
3. 셀 값이 `O` / `X` / `-` 셋 중 하나인가?
4. **자기 단계의 칸 외 다른 칸을 건드리지 않았는가?** (가장 흔한 실수)
5. **다른 WO의 행을 건드리지 않았는가?**
6. `**현재 작업**` 라인이 표 상태와 모순되지 않는가?
7. **이 커맨드의 작업이 끝났는가? 끝났으면 즉시 종료하고 사용자에게 보고하라.** 다음 단계 커맨드를 자동으로 호출하지 마라.

## 완료된 WO의 모양 (참고 예시)

```
| WO-011 | O | - | O | O | - |   ← 한 번에 통과
| WO-012 | X | O | O | O | - |   ← check 실패 → fix-check로 해결
| WO-013 | O | - | O | X | O |   ← review 실패 → fix-review로 해결
| WO-014 | X | O | O | X | O |   ← 양쪽 다 실패 → 양쪽 다 해결
```

`X` 옆 칸이 `O`이면 그 단계는 이미 해결된 상태입니다. 다시 돌릴 필요 없습니다.
